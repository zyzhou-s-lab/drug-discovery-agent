# 设计哲学：用 PL 视角设计 Agent Harness

本项目的所有架构决定都从一组程序语言理论（PL）/ 函数式编程（FP）的观念推导而来。这一页是"为什么"，[ARCHITECTURE.md](ARCHITECTURE.md) 是"怎么做"。

---

## 1. LLM 是纯函数，agent 不是

- **LLM 的一次前向计算是纯函数**：输入 prompt，输出 token；在 temperature=0 下是确定性映射，且这次调用本身**不改变外部世界**。满足纯函数两个要件：输出只依赖输入、无副作用。
- **但多轮对话把历史偷偷塞进输入**：于是"agent"变成一个**有状态对象**，行为依赖累积的 context。
- **context 污染 & 无法退出角色**：一旦模型在 context 里进过角色、做过事，这些痕迹无法干净抹除，会持续偏置后续判断。当前任何模型**只能进入角色、不能退出角色**——退出 = 丢掉整段 context（结束 session）。
- **推论**：可靠的长程系统必须**每个工作单元用全新 context**，把 agent 重新钉回"纯函数"的形态。

## 2. 真正要管理的是「副作用」，不是「进度」

- 在 FP 里，state 指的不是"做到第几步"，而是"这次计算对返回值之外的世界造成的一切扰动"。
- 记录进度的字符串、衍生文档、改动的环境……都是**副作用**，不是函数的标准输出。
- **状态机的核心职责 = 定义和约束副作用**（怎么产生、怎么被消费、怎么收口），而不只是画流程图。
- 稳定性最高的系统是**无副作用 / 可收敛**的系统（典型：只改参数、单一任务的迭代循环）。真实任务做不到纯，但 harness 的作用就是把脏现实**收敛逼近**到这个理想。

## 3. 副作用「逃逸 → 收敛」≈ 代数效应（algebraic effects / Koka）

逐词对应：

| 现象 | 代数效应概念 |
|---|---|
| 内层循环冒出一个副作用（环境崩了） | `perform` 一个 effect，在该点挂起 |
| 副作用"逃逸到系统外部" | effect 沿调用栈向上找 handler |
| 状态机派生的函数"消费副作用" | **handler** 接住并解释 |
| 修完后中断的循环继续跑 | handler `resume`，从挂起点续跑（捕获 delimited continuation） |
| "收敛回系统内部、避免不可观测黑箱" | 控制权回到 handler 这个可控边界 |

附带洞见：**"杀死模型 / 退出角色" = 一个不 resume 的 handler（异常）**；"修复后续跑" = 会 resume 的代数效应。同一套理论解释两者。**Koka** 把 effect 写进类型系统（行多态 effect 类型 + handler），是这套思想的语言级实现。

## 4. agent-as-tool（递归 / 反转）

- 普通 tool_use：**LLM 在上面当 orchestrator**，工具在下面当 leaf 函数。
- 本架构反过来：把**整个会话 agent**（LLM + 循环 + context）装进一个 schema，**让它自己变成一个工具**，由外层去调。
- 新主张：**agent 可以是 tool**。tool_use 是原子，本架构是"化学"——它在 tool_use 之上加了一层纪律：纯度、幂等、context 隔离、副作用收敛、组合。
- tool_use 本身就已经是 perform/handle/resume 形状的（perform=工具调用，handle=执行，resume=喂回结果）——所以代数效应透镜套得这么贴。

## 5. 把 agent 钉成「固定 schema 的纯函数」

- **不是**要求每次输出一模一样（常见误解）。
- 而是：**输入/输出的 schema 结构固定、类型可定义**，内部填充内容可动态变化。固定的是**形状（type）**，不是**取值（value）**。自由度从"接口"移到了"内部"。
- 类型标准化 → 行为可预期 → 稳定 → 可复用 → 才扛得住长程循环。

## 6. 工作区 = 不可信脏堆；权威数据源 = 真正的返回值

- agent 需要临时工作空间（本地磁盘）。把它**直接定义为不可信数据源**，可随时清空重来。
- 单独设**权威数据源（index）**。只有写进 index 的标准化输出才算这个纯函数的返回值。
- 好处：幂等、可复现。每次循环 context 清空都不怕，因为知识不在 context 里，在 index 里。

## 7. 未执行的副作用不算数

- "effects as values"：可以先**描述**一个副作用而不**执行**它，因此能在执行前检查、过滤、丢弃。
- 落地：**在真正 execute 前对 tool call 做 gating**。没被执行的副作用对世界零影响，异常的直接扔。

## 8. 大型信息索引化

- context 有限且会污染 → agent 需要的大体量知识（文献、数据库、几百个工具 schema、跨会话记忆）**不能住在 context 里**，必须 externalize 成**可查询的索引**，按需检索一小片。
- 形态：全文/倒排（BM25）、向量/语义（RAG）、结构化（数据库/知识图谱）、记忆索引。
- 闭环：knowledge 外置成 index → index 只能通过**检索工具**够到 → 又回到 tool_use。**index = 权威数据源的一种实现**：context 可丢弃，index 持久权威。

## 9. 「可靠长程任务」不是对话智能体，而是参数化函数

- 把上述推到结论：可靠长程层本质是 `f(config) → result`，**不是 `chat(你一句我一句)`**。Robin 就是活证据（`RobinConfiguration(disease_name=...)` 进，结果出，无人插嘴）。
- 但**对话没有消失，它被赶到了两端**：
  - **设计期 / steering**：人类把需求聊清楚，产物是一份 config（"编译"对话为参数）。
  - **执行期 / 长循环**：headless 跑，不要自由对话——自由对话 = 无界状态 = 污染。
- 这就是 **"conversational shell, functional core"**（命令式外壳 / 函数式内核）搬到 agent 上。

## 10. 两种"聪明"各自关好

- **做决策的聪明** → 关进**无状态 judge 节点**（记忆外放 index）。它**出裁决**，不**做编排**；真正 loop/route 的是那段愚蠢的确定性代码。
- **给人看的聪明** → 关进**只读 observer**（污染留在下游，伤不到主干）。
- 中间那根指挥棒，自始至终愚蠢而确定。**聪明一旦常驻在顶层，context 污染就回来，稳态就塌了。**

> 失败模式备忘：并行 SSH / 并行工具批次里一条出错会触发同级取消级联，可能损坏 thinking-block 签名，导致会话永久 400。长程编排里**远程命令串行执行**，大输出先落盘再读。
