原文
Agent 长程任务与Harness设计理论聊天整理

auto research 就是状态机驱动角色和子任务分解。 任何严谨的长任务都是这种，而不是一个会话 n 个 skill。

codex 的 goal 就是同一个 session 但是每次都不看过去的 context，设置好 tasklist 每次都跑固定流程，永远循环，直到自认为做完了解除状态机。

goal 只要模型干活了，context 就会形成刻板印象、产生污染。 所以 goal 机制存在限制：只要你完成过一个 goal，就不能再开第二个，必须开启新 session。

现在的任何模型只能进入角色不能退出角色，退出就是杀死模型，只能通过开新 session 清掉 context。

长程任务的 “长”，并不体现在单次内容长度，而是可循环所以变长。 循环中特定的步骤可以套进角色里，因此可以拆分为若干个 skill。

任何可靠的长程任务都必须依托一套 harness。 最基础的是完全无状态任务，ralph loop、goal 机制本质都是 ralph loop。 而有状态任务，必须配套状态机和路由管控。

state 指代的不是任务进度，而是一切副作用，可以用函数式编程的逻辑理解。 llm 本身是一个纯函数：输入 prompt，产出代码文件。 所有预期外、用于控制 llm 行为的内容，比如记录任务进度的字符串、代码衍生的文档，都属于副作用，不属于函数的标准输出。 状态机的核心作用，是定义和约束副作用，而非单纯定义执行流程。

稳定性最高的长程工作流程，是无副作用的系统。

典型案例：社区基于 auto research 思想开发的 auto quant。 循环过程中，llm 只负责修改量化因子的参数，只做单一任务，全程无副作用，持续运行最终可以收敛出极高胜率。

但绝大多数真实任务无法做到纯粹无副作用，必然会产生各类副作用。 举例：循环迭代代码的过程中，程序运行导致运行环境崩溃，修复环境这个行为就是典型副作用。

这类副作用会逃逸到系统外部，产生不可预知的影响。 管理副作用的核心逻辑：让所有副作用的消费过程，收敛回原系统内部。 修复环境、消除报错后，原本中断的循环迭代可以继续执行，避免形成不可观测的黑箱流程。 由状态机派生的函数，专门负责消费副作用，将逃逸的副作用拉回系统可控的原始逻辑中。

基于这套逻辑，可以延伸理解 algebraic effects（代数效应），以及 koka 编程语言的设计思想。

目前市面上所有 harness 框架，都没有触及程序语言理论（PL）的核心，但 PL 的底层思想对 Agent 工程设计极具价值。 行业很多方案走弯路，本质是完全不借鉴、不理解前人的程序语言理论成果。

Harness 的核心设计理念：将 Agent 封装为纯函数。 Agent 内部所有设计，都是为了让 llm 的行为趋近于纯函数，实现可定义类型。 类型标准化，能够大幅提升 Agent 稳定性；稳定的 Agent 可以复用，可复用才能支撑持续循环的长程任务。

客观对比业内方案： cc 的设计各方面都更加正规、偏向学院派； codex 属于野路子设计； 而当下主流的 a 系列模型，整体设计思路已经走偏。

补充关键误区纠正： 将 Agent 包装成纯函数，不是要求 Agent 每次输出内容完全一致，这是错误认知。 真正的核心是：输入、输出的 schema 结构固定、类型可定义，内部填充内容可动态变化。

Agent 运行需要临时工作空间，通常依托本地磁盘。 杂乱的本地空间无法区分有效、无效文件，最优设计逻辑： 将本地工作空间直接定义为不可信数据源，单独设立权威数据源。 权威数据源的标准化输出，就是 Agent 作为纯函数的标准输出。

副作用的可控逻辑： 人工无法完全规避副作用，但未执行的副作用不会产生任何影响，无效、异常的副作用可以直接丢弃。


解读

A. 循环、角色与 session（开头到「依托一套 harness」）
「auto research 就是状态机驱动角色和子任务分解……而不是一个会话 n 个 skill」 说的是:严肃的长任务结构应该是「一个状态机 + 若干角色（role）+ 任务分解」,而不是「在同一个对话里堆 n 个 skill 顺着聊」。区别在于:状态机有明确的状态与转移,每一步该干什么是被结构约束的;而「一个会话 n 个 skill」是线性、临时、靠 prompt 拼接的,没有可控的流程骨架。

「codex 的 goal……每次都不看过去的 context,跑固定流程,循环直到自认为做完」 描述 codex 的 goal 机制:同一个 session,但每轮刻意不带入上一轮的累积上下文,按预设 tasklist 跑固定流程,反复循环,直到模型自己判断「完成」才解除状态机。

「只要模型干活,context 就会形成刻板印象、产生污染……完成一个 goal 就不能再开第二个」 这是关键观察。一旦模型在上下文里「做过事/进过角色」,这些痕迹就留在 context 里、无法干净抹除,会持续偏置后续判断(stereotype / pollution)。所以 goal 机制有硬限制:一个 session 完成过一个 goal 后,残留污染使它没法干净地再起第二个,必须开新 session 清空 context。

「任何模型只能进入角色不能退出角色,退出就是杀死模型」 非常形象,也基本属实:Transformer 对整段历史做注意力,你没法「撤销」已经进入的角色——因为没有「减去某段 token 影响」的操作,只能把整段 context 丢掉(=结束 session = 杀死这个实例)。

补一句实践层面的近似:harness 里的 子 agent、/clear、上下文压缩/摘要 其实就是在工程上模拟「退出角色」——开一个干净的纯函数实例去做子任务,做完只把结果带回来,母 context 不被污染。这正是后面「封装成纯函数」要解决的问题。

「长程任务的『长』不是单次内容长,而是可循环所以变长;循环里特定步骤套进角色 → 拆成 skill」 「长程」的本质是可循环迭代,不是单次输出字数多。循环里某些固定步骤可以固化成一个角色,角色再封装成一个 skill。

「可靠长程任务必须依托 harness;最基础是无状态任务,ralph loop、goal 本质都是 ralph loop;有状态任务必须配状态机和路由」 这里给了一个分层:

无状态(stateless):while true 反复跑同一个 prompt,只靠文件系统/代码库当唯一持久态——这就是 ralph loop(社区俗称,源自「Ralph」式暴力循环)。goal 本质也是它。
有状态(stateful):存在需要管理的副作用,就必须上**状态机 + 路由(routing)**来管控流程走向。
B. 核心重定义:state = 副作用,而不是进度
「state 不是任务进度,而是一切副作用,可以用函数式编程理解」 这是全文最重要的一次概念替换,而且是对的。在 FP 里,state 指的不是「我做到第几步」,而是「这次计算对返回值之外的世界造成的一切扰动」。

「LLM 本身是纯函数:输入 prompt,产出代码」 准确说:LLM 的一次前向计算,在 temperature=0 时是确定性映射(同输入 → 同输出),而且这次调用本身不改变外部世界——它只是把 token 映射成 token。这就满足纯函数的两个要件:输出只依赖输入、无副作用。

「记录进度的字符串、衍生文档……都属于副作用,不属于标准输出。状态机的核心是定义和约束副作用,而非定义执行流程」 顺着上面:凡是「为了控制 LLM 行为而存在、却不是它那一份标准产出」的东西——进度记录、临时笔记、派生文档——都是副作用,不是函数的 return value。于是状态机的真正职责被重新定位:它管的是副作用(怎么产生、怎么被消费、怎么收口),而不只是画一张流程图。这跟 effect handler 的定位完全一致(见 C)。

C. 副作用「逃逸 → 收敛」= 代数效应 / Koka(这段是全文的理论内核)
「稳定性最高的工作流,是无副作用的系统」——纯/幂等的系统最可靠,因为可以随时重启、随时重放、结果可复现。

auto quant 案例:在 auto research 的循环里,LLM 只改量化因子的参数,单一任务、全程无副作用,于是可以放心地一直循环,最终收敛。

这个机制是合理的(纯函数 + 迭代 = 可收敛的搜索);但「极高胜率」是经验性强断言,理解机制即可,别把它当成保证。

「真实任务必然有副作用:迭代代码时程序把运行环境搞崩,修环境就是典型副作用」——对。环境崩了去修,这个动作不在「改代码 → 出代码」的纯函数语义里,是逃出来的副作用。

「管理副作用的核心:让副作用的消费过程收敛回原系统内部……修完环境后中断的循环可以继续……由状态机派生的函数专门消费副作用,把逃逸的副作用拉回原始逻辑」

这一整段,逐词对应的就是 algebraic effects(代数效应)的 perform / handle / resume 模型,这也是为什么紧接着点名 Koka。对应关系:

原文说法	代数效应里的概念
内层循环里冒出一个副作用(环境崩了)	计算 perform(raise) 一个 effect,在该点挂起
副作用「逃逸到系统外部」	effect 沿调用栈向上传递,寻找 handler
状态机派生的函数「专门消费副作用」	handler(effect handler) 接住并解释这个 effect
「修完后中断的循环继续执行」	handler 调 resume,从 perform 那一点续跑(本质是捕获了 delimited continuation)
「收敛回系统内部、避免不可观测黑箱」	控制权回到 handler 这个可控边界,而不是散落在外部
一个很漂亮的延伸:「退出角色 = 杀死模型」其实就是一个不 resume 的 handler——异常(exception)正是「永不恢复」的代数效应特例;而「修好后续跑」是「会 resume」的代数效应。同一套理论同时解释了这两件事。

Koka 就是把这套做进类型系统的研究语言(Daan Leijen / 微软研究院):它用行多态的 effect 类型在函数签名里显式标注这个函数会产生哪些副作用,再用 handler 统一接管。把它的思想搬到 harness,就是:让每个 agent 的副作用变成「可声明、可被外层 handler 收口、可恢复」的东西,而不是散逸的、不可观测的黑箱。

D. Harness 的核心理念:把 Agent 封装成纯函数
「现有 harness 都没触及 PL 核心,但 PL 思想极有价值;走弯路是因为不借鉴前人成果」——延续上次聊的:agent 圈子大多从工程/ML 背景进来,没接触过这套几十年沉淀的理论,于是重复造轮子。

「Harness 核心:把 Agent 封装为纯函数;内部一切设计都为了让 LLM 行为趋近纯函数、实现可定义类型;类型标准化 → 稳定 → 可复用 → 支撑持续循环」 逻辑链是:类型/schema 固定 → 行为可预期 → 稳定 → 可复用 → 才能放进循环里反复调用。这对应到实际工程就是 structured output / tool schema / 强制 JSON schema 这类东西——把 I/O 钉死成契约,agent 才能像零件一样被组合和重复调用。

误区纠正(很重要):「封装成纯函数 ≠ 每次输出一模一样」 这是最容易误解的点,作者特意澄清:纯函数要求的是输入、输出的 schema 结构固定、类型可定义,至于 schema 里填什么内容,可以每次动态变化。换句话说,固定的是形状(type),不是取值(value)。{plan: string, files: string[]} 这个类型每次都满足,里面具体写什么允许变——这才是「纯函数化」的真实含义。

E. 工作空间 vs 权威数据源
「agent 需要临时工作空间(本地磁盘);杂乱空间分不清有效/无效文件;最优做法:把本地工作空间直接定义为不可信数据源,单独设权威数据源;权威源的标准化输出 = agent 作为纯函数的标准输出」

这是很扎实的工程原则,对应**「可丢弃的脏 scratch」与「权威产物存储」分离**:

本地工作区 = 计算过程中的堆(heap)/草稿,默认不可信、可随时清空重来;
权威数据源 = 真正被认可的产物(类比 git / artifact store / 计算的 return value);
只有权威源里的标准化输出才算这个纯函数的返回值。 带来的好处就是幂等与可复现:你可以把工作区整个删掉重跑,只要权威输出一致,系统行为就一致——这正是 B 段「无副作用最稳」在落地层面的体现。
F. 未执行的副作用不算数
「人工无法完全规避副作用,但未执行的副作用不产生任何影响,无效/异常的副作用可以直接丢弃」

对应 FP 里 「effects as values(把副作用当成值)」 的思想:你可以先描述一个副作用而不执行它(像 Haskell 里的 IO a 只是一段「待执行的描述」)。既然只是描述,就可以在执行前检查、过滤、丢弃。 落到 harness:在真正 execute 之前对 tool call 做 gating/审批/筛选——没被执行的工具调用对世界零影响,异常的直接扔掉。这就是为什么「在执行前拦截副作用」这么强:它把不可控的外部扰动,挡在了系统可控边界之内。

G. 业内对比(这部分是观点,不是事实判断)
「cc 更正规、偏学院派;codex 是野路子;当下主流的 a 系列模型整体走偏」 这是作者的主观评价:Claude Code(cc)设计更体系化/学院派,Codex 偏 hacky,「a 系列」被认为方向跑偏。

说明一下:cc=Claude Code、codex=OpenAI Codex 比较明确;「a 系列模型」指代不明(可能指某家以 a 开头的产品/模型族,也可能是泛指)。这一句当成个人立场看即可,不必当结论。

一句话把整段串起来
LLM 是纯函数(token→token,本身不动世界)→ 但多轮对话把历史偷偷塞进输入,于是 agent 变成有状态对象、context 被污染且无法退出角色 → 所以真正要管的不是「进度」而是副作用 → 用状态机 = effect handler 来 perform/handle/resume,把逃逸的副作用收敛回来、让中断的循环续跑(这就是代数效应 / Koka)→ 工作区是可丢弃的脏堆,权威数据源才是返回值 → 没执行的副作用不算数,可随时丢弃。把 agent 钉成固定 schema/类型的纯函数,它才稳定、可复用,才扛得住长程循环。

整段其实是一篇**「用代数效应那套 PL 思想来设计 agent harness」**的纲领。核心映射(LLM=纯函数、state=副作用、状态机=handler、逃逸→resume)都站得住;偏经验/主观的部分是 auto quant 的胜率和三家方案的优劣评判。
